# NOW

## Project

Human-AI Workbench

## Current goal

Test whether a very small working protocol can help a human and fresh AI continue long-lived projects without making coordination itself the main job.

## Where we are

- The repository has been initialized with practical templates rather than a constitution or abstract governance model.
- The current working set is README + PROJECT-PLAN + NOW + HANDOFF + optional DECISION + experiments.
- Concrete defaults now exist for handoff depth, active work, and takeover behavior.
- ENA will be the first real project used to test the workbench, but ENA-specific needs do not automatically become workbench rules.

## What changed recently

- Normal handoff default: 10 user/assistant exchanges.
- Light: 5 exchanges.
- Deep: 15–20 exchanges by default.
- Earlier selected context: up to 3 items by default.
- Full project audit is no longer the default takeover behavior.
- New structure should grow from repeated pain, not imagined future needs.

## Current problems / unknowns

- Is 10 exchanges enough for real continuity?
- Is a 1,500-word `NOW.md` ceiling too generous or too restrictive?
- Which parts of ENA's old maintenance machinery are genuinely needed when using this lighter workflow?
- Does this working method transfer well to a second, non-ENA project?

## Next consequential action

Use this workbench to simplify and continue ENA: create an ENA-specific `NOW.md`/handoff using the new templates, then give a fresh AI only that minimal surface and observe what it misses, repeats, or over-audits.

## Do not redo

- Do not turn this repository into a constitution.
- Do not migrate ENA's old governance machinery wholesale.
- Do not add templates merely because they might someday be useful.
- Do not equate more project-management artifacts with better continuity.
